# Pixel Evolution — AI の「選択」だけで絵は生まれるか

進化論の自然選択説をモデルにした、AI の思考を探る実験です。

1. 32×32 のウィンドウの全ピクセルに、7色（黒・白・赤・緑・青・黄・シアン）のどれかをランダムに割り当てる
2. 毎世代、**ほぼ同じ2つのウィンドウ**を用意する
   - 片方は鋳型（親）をそのままコピーしたもの
   - もう片方は鋳型から**ランダムな10ピクセル**だけ色を変えたもの（変異体）
3. ユーザーが与えたお題（概念）について、Claude が「どちらがよりお題に沿っているか」を選ぶ
4. 選ばれたウィンドウが次の世代の鋳型になる
5. これを繰り返し、画面に何か consistent なものが現れてくるかを観察する

変異体が選ばれなければ親が生き残るので、一度得た「良さ」は失われません（累積選択）。

## セットアップ

```bash
pip install -r requirements.txt
```

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

## 使い方

```bash
python evolve.py "海" --generations 200
```

```bash
python evolve.py "怒り" -g 300 --seed 42
```

途中で Ctrl+C しても状態は毎世代保存されているので、続きから再開できます:

```bash
python evolve.py --resume runs/20261109-120000_海 -g 200
```

### 対照実験（選択圧なし）

`--judge random` にすると、Claude の代わりにコイン投げで選びます（API キー不要）。
Claude で回した結果と見比べることで、「現れた形が本当に Claude の選択によるものか、ただの偶然の浮動か」を区別できます。

```bash
python evolve.py "海" --judge random -g 300 --seed 42
```

### 主なオプション

| オプション | 既定値 | 意味 |
|---|---|---|
| `-g, --generations` | 100 | 今回回す世代数 |
| `--size` | 32 | グリッドの一辺のピクセル数 |
| `--mutations` | 10 | 1世代で変えるピクセル数 |
| `--scale` | 16 | Claude に見せる画像の拡大率（32×16 = 512px） |
| `--effort` | medium | Claude がどれだけ考えるか（low / medium / high / xhigh / max） |
| `--model` | claude-opus-5-5 | 判定に使うモデル |
| `--seed` | なし | 乱数シード。同じシードなら初期画像と変異の位置が再現される |
| `--snapshot-every` | 5 | 何世代ごとに鋳型の画像を保存するか |

## 出力（`runs/<日時>_<お題>/`）

| ファイル | 内容 |
|---|---|
| `live.png` | 直近の世代。左 = 親、右 = 変異体（変異ピクセルをマゼンタの枠で表示）、選ばれた方が緑枠 |
| `current.png` | 現在の鋳型（拡大） |
| `timeline.png` | 世代ごとの鋳型の一覧 |
| `evolution.gif` | 進化のアニメーション |
| `log.jsonl` | 全世代の記録。Claude の選択・**理由**・**思考の要約**を含む |
| `config.json` / `state.*` | 設定と再開用の状態 |

`live.png` は毎世代上書きされるので、自動更新する画像ビューアで開いておくと進化をリアルタイムで眺められます。

## 実験の設計上の工夫

- **位置バイアス対策**: 変異体を A（先）と B（後）のどちらに置くかを毎世代ランダムにしています。
  実行の最後に「A を選んだ割合」が表示されるので、50% から大きくずれていれば Claude に位置の癖があると分かります。
- **Claude には変異位置を教えない**: Claude に見せるのは2枚の画像とお題だけです。マゼンタの枠は人間用の `live.png` にだけ描かれます。
- **判定できなかった世代**: 拒否・出力の解析失敗などで判定できなかった場合は、親を残してその世代を飛ばします（`log.jsonl` の `status` に記録）。

## 費用の目安

1世代につき API 呼び出しが1回です（画像2枚 + 短い回答 + 思考）。
`--effort medium` で1世代あたりおおよそ数セント程度なので、数百世代回す前に `-g 20` 程度で試して、
最後に表示されるトークン数から見積もるのがおすすめです。`--effort low` にすると安く速くなります。

## 手動判定（会話中の Claude が判定）を試した記録

API を使わずに判定する `manual_step.py` で、お題「顔」・シード42（対照実験と同じ初期画像と変異位置）を試した。

| 見せ方 | 世代 | 結果 |
|---|---|---|
| A と B を横に並べた1枚の画像 | 1〜4 | 毎回 B（右側）を選択。変異体は A・B・A・A の位置にあり、変異体を選べたのは1回だけ。実際は10ピクセルしか違わないのに、並べると「全体が別の絵」に見え、もっともらしい理由を付けて右側を選び続けていた（位置の偏り） |
| A と B を単独の画像として1枚ずつ | 5〜6 | 錯覚は消え、2枚はほぼ同一に見えるようになった。ただし 32×32 の中の10ピクセル（約1%）の差は判別できず、選択は実質コイン投げ |

この条件では、画像を見て判定する Claude は変異の差を読み取れず、選択圧がかからない。

### 16×16 に変えて続けた結果（お題「顔」・シード42・40世代）

`runs/20261109-101324_顔_manual/`（対照: `runs/20261109-101323_顔/`、同じ初期画像と変異位置）

- セルが大きくなったことで、10ピクセル（約4%）の差は見分けられるようになった
- A を選んだ割合は 21/40（52%）で、位置の偏りは消えた
- 変異体を採用したのは 6/40（15%）。対照実験（コイン投げ）の最初の40世代は 18/40
- 初期画像から変わったピクセルは 55 個
- 判定の基準は一貫して「上部の暗い対＝目、下中央の黒い横並び＝口、中央の縦線＝鼻」を強めるか崩すか。
  ほとんどの変異は「顔の部品を崩す」と判断して退けた
- 40世代の時点では、人が見て顔と分かるものは現れていない（`comparison.png`: 左から初期 / 手動判定40世代 / 対照40世代）
